## 3. 场景验收明细（test/scenarios.py）

1. **投稿配图**：82.6 mm / 600 dpi，1951 px，留白 11.0%，PDF 234.1 pt 且为矢量。
2. **看图读结构**：自绘图经 DECIMER 读回，InChIKey 与目标一致；单引擎结果标「需人工确认」。
3. **作业批改**：4 份答案 → 正确 1 / 取代基不同 1 / 不对 1 / 读不出 1，得分 25.0，Word 报告 37 KB。
4. **配平与投料**：系数 [1,1,1,1]，乙酸乙酯 881.06 mg，水为副产物，质量闭合 0.00 mg。
5. **同系列出题**：3×3 组合库 9 个结构，联系表一次画出 9 个，文件 112 KB。
6. **结构性质表**：4 个结构 → 性质表 → Word SI 表 + xlsx，行数一致。
7. **报告文档**：docx 内含 1 张图（word/media/image1.png），图注与正文都在；明确写出没有 OLE。
8. **库与模型**：SQLite 存 4 个、子结构查 2 个命中、SDF 往返 4 条、模型 CV R² 0.58、预测在适用域内。
9. **谱图与逆合成**：4 个观测峰全部被结构解释；乙酸乙酯逆推得到乙酸 + 乙醇。

## 4. 部署验证（W9 + W11，改自包含安装后重测）

安装形态：`python tools/install_plugin.py` 复制到 `~/.dsh/plugins/dsh-chem`，**不是 link**。

- 副本：69 文件 / 926 KB，其中 60 个 .py（`engine/bin/chem.py` + `engine/core/**`）；`--check` 逐文件哈希一致。
- `data` → `%LOCALAPPDATA%/dsh-chem` 的 junction：venv 574 MB、`library.db`、`models/` 都在机器级，
  重装插件不重装依赖。
- 安装里已无 `dsh-plugin/lib/{bridge.js,config.js}`：这两个是 v1/v2 遗留、无人 import，

## 4c. 面板契约测试发现的真问题

`test/w10_panel.mjs` 第一次跑就抓到：`client.js` 的 `PLUGIN_ID` 还是改名前的 `dsh-chem-draw-tool`，
而桥返回 `dsh-chem` —— `discover()` 永远匹配不上，面板会找不到自己的后端。已修正为同名并入断言。
这条正是「重启后视觉没截图」那个缺口能机械覆盖的部分：端点、动词、同名、注册点现在都有断言。

桥实际落地 7 条路由：**3 个数据端点**（`/state`、`/artifacts`、`/call`）+ 4 条辅助
（`/health` 认门牌、`/client-mounted` 面板挂载回执、`/artifact` 按名取文件、`/latest.png` 最近一张图）。

## 5. 没验的部分（不假装验过）

- 桌面版 GUI 重启后「化学绘图」面板的**视觉呈现**：面板已通过语法检查与桥端到端测试，但没有在重启后的
  真实窗口里截图确认。用户重开 DSH 即可看到，若未出现按 `~/.dsh/plugins/dsh-chem/docs/` 的排查清单走。
- 二进制 `.cdx` / EPS / Word OLE：受 ChemDraw 本机接口限制，见根 README「诚实的边界」。
- KingDraw 通道：本机无可验证的 ProgID 驱动方式，未接线。
- **没有 GitHub Actions**：本机无法执行 workflow，写一个没跑过的 CI 只会得到一个红的徽章。
  门禁以本地命令形式存在（上表），克隆后照跑即可；`test/w9` 与 `test/w10` 的路径从文件自身推导，
  已在另一目录的 `git archive` 副本里跑通 w10 11/11。

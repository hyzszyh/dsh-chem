# chem-draw-tool v2 工程要求

> 状态：草案 v2.0（第一版，供评审）。v1 已归档到标签 `archive/v1-engine-layer`，说明见 [ARCHIVE.md](../../ARCHIVE.md)。
> 一句话：**化学专业的学生/教师不打开 ChemDraw 或 KingDraw，把想法告诉 agent，agent 交付能直接用的产物。**

## 1. 调用者变了：这决定一切

v1 的调用者是人，会自己把动作拼成任务；v2 的调用者是 agent，它有三个硬约束：

1. **调用轮次是成本**：每一步都要读返回再决策，所以一个任务一次调用。
2. **它看不见屏幕**：任何绘图结果都必须带回一张可渲染的预览图，否则它无法自检、用户还得自己开软件。
3. **它说人话**：学生会说「阿司匹林」「64-19-7」「照着这张截图画」，不会说 SMILES。

由此得出五条设计铁律：任务级聚合、视觉反馈、身份随产物、状态可查、失败给下一步。

## 2. 用户与场景

- **U1 无 license 的学生**：没有 ChemDraw，只有 KingDraw 或什么都没有。需要出作业图、性质表。
- **U2 有 ChemDraw 的学生**：要交实验报告、要按老师要求画结构、要检查自己画得对不对。
- **U3 教师/助教**：出题、出讲义、批改几十份结构图。
- **U4 研究生**：投稿图（尺寸/DPI 被期刊卡死）、SI 表征表、反应式与机理图。
- **U5 计算化学方向**：2D→3D 取初始构象、送 Gaussian/ORCA。

## 3. 功能需求

每条格式：编号 · 要求 · 交付 · 验收 · 依赖引擎。

### 3.1 输入解析（把想法变成结构）

- **FR-I1 名称解析**：中英文俗名、商品名、IUPAC 名、CAS 号 → 结构 + 解析来源 + 置信度。
  交付：SMILES/InChIKey/分子式 + `source`。验收：阿司匹林、对乙酰氨基酚、64-19-7 三个都能出。
  依赖：本地词典 → OPSIN（Java）→ PubChem（联网）。
- **FR-I2 图像解析**：截图/PDF 插图/手写照片 → 候选结构 + 置信度 + 裁剪图。
  验收：单分子截图给出 ≥1 个通过 RDKit 价键校验的候选；低置信时返回候选列表而不是猜。
  依赖：MolScribe / DECIMER / OSRA / MolVec + LLM 视觉 + 一致性投票（见 §6）。
- **FR-I3 表达式解析**：SMILES / InChI / 分子式 / 自然语言描述（「对位有羟基的苯甲醛」）→ 结构 + 校验。
  验收：自然语言描述先由 LLM 生成 SMILES，再交 RDKit 校验；校验失败必须重试或明说解析不出。
- **FR-I4 文件导入**：`.cdx` `.cdxml` `.mol` `.sdf` `.king` 与图片。验收：读回的结构 InChIKey 与原文件一致。

### 3.2 编辑与作图

- **FR-D1 单结构落地**：SMILES/名称/molblock → 画到 ChemDraw 页面并**读回核对**，返回预览图。
  验收：读回 SMILES 的 InChIKey 等于输入；预览图字节 > 0 且可渲染。
- **FR-D2 批量与排版**：一次 N 个结构，网格排布、统一风格，输出 N 张图 + 联系表。
  验收：8 个分子一张图，无重叠（用包围盒检测），风格一致（同一键长/字号）。
- **FR-D3 结构修改**：替换/删除基团、加原子、改电荷、标孤对电子。验收：改后读回与预期 InChIKey 一致。
- **FR-D4 排版整理**：Clean Up Structure/Reaction、对齐、居中、键长统一。**依赖命令面**（§5）。
- **FR-D5 立体化学**：楔形键、R/S 标注、Fischer / Newman / 透视式。验收：立体中心数与标注数一致。
- **FR-D6 反应式**：反应物/产物/条件/箭头 + 原子映射 + 自动编号。验收：映射后每个产物原子可追溯到反应物。
- **FR-D7 机理弯箭头**：电子进攻弯箭头（起点/终点/箭头类型）。验收：`IsArc=True` 且导出图可见。
- **FR-D8 通式/Markush**：R 基团、可变取代、展开成具体结构或 SDF。验收：展开数量与组合数一致。
- **FR-D9 生物大分子**：肽/DNA/RNA 序列、HELM 互转、质粒图。验收：序列 → 结构 → 序列往返一致。
- **FR-D10 辅助对象**：TLC 板（含 Rf 标注）、轨道图、表格对象、原子编号。
- **FR-D11 复杂分子分级**：按原子数分档并给出各自的时间与出图策略，不许一句「支持」了事。
  分档：常规 <100、中等 100–300、大 300–800、天然产物量级 >800（岩沙海葵毒素 C129H223N3O54 属此档）。
  每档必须报告：插入耗时、导出耗时、建议画布宽度（mm）、是否必须分块。验收：见 §16 实测表。
- **FR-D12 大分子可读性**：整幅缩放到固定宽度会让原子挤成一团（实测 400 原子导出图字节数反而下降），
  所以必须提供**可读性判据**：导出图上平均键长像素数低于阈值时，自动改为加宽画布或分块平铺，
  并在返回里写清「这张图在 170 mm 下不可读，已按 320 mm 导出」。**不许交付一张看不清的图。**

### 3.3 校验

- **FR-V1 结构体检**：价键错误、立体冲突、重叠、化学警告逐条 + 修法建议。**依赖命令面 `Check Structure`**。
  验收：故意画一个五价碳，必须报出来并给修法。
- **FR-V2 身份核对**：InChIKey 跨引擎对账（v1 已有）。验收：两引擎不一致时返回差异而不是选一个。
- **FR-V3 计量核算**：当量、摩尔质量、投料量、产率表。**依赖命令面 `Analyze Stoichiometry`**。
  验收：给定 1.0 equiv 底物 + 1.2 equiv 试剂，输出质量精确到 0.1 mg。
- **FR-V4 谱学**：¹H/¹³C 预测与谱-结构归属。**依赖命令面 `Predict ¹H-NMR / ¹³C-NMR Shifts`**。
  验收：结果作为文本/表格返回，并注明「预测值，非实验值」。

### 3.4 产出

- **FR-O1 期刊图**：预设（中文期刊单栏 8 cm、图式 17 cm、ACS 单栏、RSC、Nature）+ 自定义；dpi；trim；
  实测像素与 dpi 一并回报。验收：输出的实际宽度与预设一致（±0.5 mm）。
- **FR-O2 讲义/试卷/PPT**：透明底 PNG、EMF 矢量、联系表。验收：粘进 Word/PPT 不失真。
- **FR-O3 性质表**：分子式、精确质量、MW、logP、TPSA、HBD/HBA、电荷、立体中心，可直接粘进 SI。
- **FR-O4 格式导出**：SDF / CSV / CDXML / .king / mol / InChI / PNG / SVG / EPS / TIFF。
- **FR-O5 3D**：构象生成、3D 属性、计算输入文件（gjf/xyz）。引擎优先级：ChemDraw 命令面 → KingDraw → RDKit。

### 3.5 教学

- **FR-T1 批量批改**：N 份学生结构 vs 答案，逐份给出差异（多余/缺失/价键错/立体错）。
- **FR-T2 出题变体**：给定骨架与取代基集合，生成变体 + 题面图 + 答案。
- **FR-T3 演示包**：TLC 板、轨道图、分步机理（每步一张图）。

### 3.6 状态与运维

- **FR-S1 状态查询**：通道可用性、打开的文档与页面、锁持有者、上次动作。无副作用。
- **FR-S2 能力目录**：能做哪些任务、用哪个工具、前置条件、证据等级——解决「学生不知道怎么开口」。
- **FR-S3 命令面执行器**：按命令名执行 ChemDraw 菜单命令，**执行前后取 CDXML 指纹**，没变化就报未生效。
- **FR-S4 收尾**：关文档/关窗口/清理暂存文件，并报告还剩什么。

## 4. 非功能需求

- **NFR-1 幂等**：同一请求重复执行，不产生重复对象或半成品文件。
- **NFR-2 并发**：多个 agent 同时调用必须排队（沿用 v1 的命名互斥锁），不许互相覆盖文档。
- **NFR-3 降级诚实**：换引擎、丢立体、丢同位素、丢置信度，都必须写进 `degraded.lost`。
- **NFR-4 性能预算**：单个任务 ≤3 s（不含启动应用）；首次冷启动 ≤20 s；预览图 ≤1 MB。
- **NFR-5 离线可用**：无网络时，画图/体检/性质/出图全部可用；只有名称解析与 OCR 降级并明说。
- **NFR-6 不破坏现场**：不杀用户进程、不覆盖已有文件、不动用户已打开的文档（除非明确要求）。
- **NFR-7 可观测**：每次调用返回 `elapsed_ms`、`evidence`、执行过的命令与文档指纹变化。
- **NFR-8 可移植**：没有 ChemDraw 时降级到 KingDraw 或 RDKit，并在 `chem_status` 里说清缺什么。
- **NFR-9 安全**：命令面只允许白名单命令；不执行任意脚本；OCR/LLM 结果一律经 RDKit 校验后才落盘。
- **NFR-10 零干扰**：交付版本默认全后台，禁抢焦点、禁弹控制台、禁阻塞式对话框（见 §15）。
- **NFR-11 双轨隔离**：ChemDraw 与 KingDraw 是两条独立路线，互不 import、各有独立锁与状态、
  只经中性格式交换（molblock/SDF/InChIKey），一路崩溃不影响另一路（见 §14）。
- **NFR-12 长任务可中断**：>10 s 的任务必须能超时中断并留下可诊断信息，不许把应用挂在半路。

## 5. 引擎矩阵与降级链

- **ChemDraw COM**：画、导出、回读、对象创建（TLC/轨道/表格/质粒/箭头/Markush）。最稳，但只有 40+ 对象。
- **ChemDraw 命令面**：357 条菜单命令里的高级能力（Clean Up、Check Structure、3D、NMR、计量表、原子映射、
  展开 SDF）。实测：`item.Execute()` 抛错、`WM_COMMAND` 会把应用打死，**只能用 UI 自动化 + 指纹校验**。
- **KingDraw**：格式转换、分子式、`.king` 读写、3D、打开确认；不需要 license。
- **RDKit**：身份、性质、价键校验、子结构匹配。所有候选的最终裁决者。
- **OCSR 引擎**：MolScribe（`pip install MolScribe`，可返回置信度）、DECIMER（`pip install decimer`）、
  OSRA（可执行）、MolVec（Java）。
- **LLM**：自然语言 → SMILES 假设、图像 → 候选假设、结果解释。**只提假设，不做最终裁决。**

降级链示例（出图）：ChemDraw COM → ChemDraw 命令面 → KingDraw 导出 → RDKit 本地渲染（标注为预览级）。

## 6. 图像识别：LLM + 专用引擎一起上

单靠大模型视觉在结构式上不可靠，单靠专用引擎在版式复杂时也不可靠。所以做**四方投票 + 化学裁决**：

1. **多方独立识别**：MolScribe、DECIMER、LLM 视觉（可用时）、OSRA/MolVec（可用时）各出一份候选。
2. **化学裁决**：每个候选过 RDKit 价键/芳香性/电荷校验，不合格直接淘汰。
3. **一致性投票**：InChIKey 相同者合并计数；≥2 方一致 → 高置信；仅 1 方 → 低置信。
4. **差异解释**：不一致时返回候选列表 + 差异点（多一个取代基/少一个双键），并附裁剪图。
5. **人工确认**：低置信不猜，把候选交回 agent 让用户指认；确认后落盘。
6. **预处理先做**：去背景、二值化、放大到 300 dpi 等效、裁边——这一步比换模型更有效。

验收：一张干净的教材结构图必须高置信命中；一张手机翻拍的模糊图必须给出候选并明确标注低置信。

**本机落地（2026-10-29 实测）**：引擎之间不共享运行时，各自一个环境，由 `ocr.py` 用子进程调用，
主进程（驱动 ChemDraw 的那个）不 import torch、不 import TensorFlow。

| 引擎 | 形态 | 命中 | 耗时 |
|---|---|---|---|
| MolVec 0.9.8 | Java jar 1.3 MB | 6/6 | 7.4 s（1.2/图） |
| DECIMER 2.8 | 独立 venv，权重 298 MB | 6/6 | 43.6 s（8.5/图） |
| MolScribe | 独立 venv（复用 torch） | 缺 onmt | — |
| OSRA | 无 Windows 二进制 | 未装 | — |

回归集是自带答案的：先用本工具把已知 SMILES 画成图，再让引擎读回来，最后比 InChIKey
（`python tools/ocr_regression.py`）。含手性分子 (S)-布洛芬，两个引擎都读出了正确立体。
单个引擎只算候选，两个引擎一致才算高置信——这条现在有真实数据支撑，不再只是设计。

## 7. 接口契约

工具（15 个，已实现并可经 MCP 调用）：`chem_status`、`chem_draw`、`chem_figure`、`chem_batch`、
`chem_convert`、`chem_analyze`、`chem_check`、`chem_stoich`、`chem_3d`、`chem_resolve`、`chem_ocr`、
`chem_grade`、`chem_variants`、`chem_close`。`chem_command`（菜单驱动）保留为实验工具，不进工具表。

返回信封在 v1 基础上扩展（见 `docs/agent-interface.md` §5）：增加 `artifacts`（含预览图）、`identity`、
`state`、`failure.next_steps`。

## 8. 里程碑

- **M1 最小闭环**：`chem_status` + `chem_draw`（含预览）+ `chem_close`。验收：一句话画出结构并在 agent 里看见图。
- **M2 批量与产出**：`chem_batch`、`chem_figure`（预设）、`chem_convert`、`chem_analyze`。
- **M3 命令面**：`chem_command` + `chem_check` + `chem_cleanup` + `chem_reaction` + `chem_stereo`。
- **M4 输入扩展**：`chem_resolve`（名称/CAS）、`chem_ocr`（多方投票）。
- **M5 教学**：批量批改、出题变体、演示包。

## 9. 验收方式

八个端到端剧本，在真实 DSH 会话里跑，记录**工具调用次数 / 人工介入次数 / 产物可交付性**：

1. 「画一下阿司匹林，给我 8 cm 单栏图」→ 2 次调用，0 次人工。
2. 「把这 8 个分子画成一张作业图」→ 1 次 `chem_batch`。
3. 「检查我这个结构画得对不对」→ 1 次 `chem_check`，报出五价碳。
4. 「按这个配比算投料量」→ 1 次 `chem_reaction`/计量，误差 ≤0.1 mg。
5. 「照着这张截图画出来」→ 1 次 `chem_ocr`，高置信命中。
6. 「64-19-7 是什么，画出来」→ 2 次调用。
7. 「画个酯化反应，标条件」→ 1 次 `chem_reaction`。
8. 「批这 10 份学生结构」→ 1 次 `chem_batch` + `chem_check`，给出逐份差异。

判据：≤3 次调用、0 次打开厂商软件界面、产物无需返工。

## 10. 风险登记

- **R1 命令面脆弱**：`Execute()` 抛错、`WM_COMMAND` 杀死应用（已实测）。缓解：只用 UI 自动化 + 前后指纹校验 +
  失败即报未生效；命令白名单。
- **R2 OCR 精度**：模糊图、多分子同图、反应式。缓解：多方投票 + 低置信不猜 + 返回裁剪图。
- **R3 LLM 幻觉**：可能编一个不存在的结构。缓解：一律 RDKit 校验，Illegal valence 直接淘汰。
- **R4 版本差异**：本机 ChemDraw 25 有 357 条命令，别的版本可能不同。缓解：能力目录运行时探测，不写死。
- **R5 ChemScript 缺失**：本机未安装，名称转换命令也不存在。缓解：走 OPSIN/PubChem。
- **R6 许可证**：无 ChemDraw 的用户只能用 KingDraw/RDKit 路径，必须在 `chem_status` 里说清。

## 12. 未验证项（诚实列出）

- UI 自动化点击 ChemDraw 菜单**尚未跑通**：UIA 能看到 13 个顶级菜单，但当前自动化实例在收到合成输入后
  失联（COM 报「对象没有连接到服务器」）。M3 前必须先解决这一条，否则 3D/NMR/计量表全部落在纸面上。
- ChemScript 未安装，`File > Run ChemScript` 的实际行为未测。
- OCR 引擎已实测：MolVec 6/6（1.2 s/图）、DECIMER 6/6（8.5 s/图），见 §6 的表；MolScribe 仍缺 onmt。
- 中文俗名解析的覆盖率未测（本地词典需自建，规模未知）。
**FR-D6 反应式（箭头 + 条件 + 原子映射 + 编号）：四项齐了，来源分两半**。

- `reaction` 动词把 A.B>>C.D 解析成两侧结构，逐原子做映射（精确签名优先，不一致的按
  元素+邻接回落，仍不唯一的标 `created` 并计入 `warnings`），生成带映射号的 RXN 块交给
  ChemDraw 排版：「反应物 + 加号 + 箭头 + 产物 + 上标映射号」由厂商画。
  实测酯化：7 个产物原子中 5 个精确匹配、2 个判为新建，如实写进返回。
- **条件文字由本工具合成**：ChemDraw 侧两条路都不通——CDXML `<t p>` 坐标被忽略
  （两个不同 y 得到字节完全相同的图）；带 Text 标签的伪原子能按坐标落位，但把它和结构放进
  同一个 payload，箭头图形就消失；分成两个 payload，第二个又被丢到内容中心。
  所以条件由 PIL 叠到导出图上（顶部白带 + 居中文本），返回里写明
  「conditions are composited onto the figure by this tool」——图能用，机制不装。
- **NMR（FR-V4）不交付**，理由见 §17（命令面驱动不了，自己写经验模型会骗人）。
## 17. M3 实施决定：能算的自己算，不能算的说清楚

§5 原来把 3D、体检、计量、NMR 全押在「命令面」上。实测之后改了主意，证据在下面。

### 实测：三条驱动菜单的死路

1. **UIA 展开有效，点击无效**：`MenuItem.expand()` 能展开 Structure 菜单（出现 45 个条目，含
   `Toggle Aromatic Display`），但条目 `invoke()` 抛 `NoPatternInterfaceError`，`click_input()` 虽不报错，
   导出图哈希前后一致——命令没生效。
2. **UIA 与 COM 混在同一进程会崩**：同一脚本里先用 pywin32 调 COM、再走 UIA、再回 COM，
   进程直接段错误（exit 139），ChemDraw 本身还活着。
3. **纯键盘路线不生效**：`Alt+S` 打开 Structure、按 `T`、回车，导出哈希前后一致——菜单加速键没有命中条目。
   顺带确认：`PostMessage(WM_COMMAND, 356)` 会打死应用（§9 已记）。

结论：**命令面不作为产品能力交付**。`v2/command.py` 保留为实验性工具（它诚实地返回
「page is byte-identical; not applied」），但没有任何任务动词依赖它。

### 替代实现（已落地，全部可测）

- **3D（FR-O5）**：RDKit `ETKDGv3` 嵌入 + `MMFF94` 优化，输出 `.mol` + `.xyz`，报告能量与是否收敛。
  这比走菜单更该做：构象是**确定性计算**，不需要 GUI，也不受许可证限制。KingDraw 的 `smiles2d_to_3d`
  作为第二引擎可选。
- **计量核算（FR-V3）**：`stoich.py` 自己算当量、mmol、质量、按收率折算；产物质量标注为**理论值、
  1:1 转化假设**，不假装是产率。
- **结构体检（FR-V1）**：`checks.py` 用 RDKit 证明价键/电荷/碎片/未定立体，再叠加页面上
  原子重叠检测（距离 < 0.6 × 中位键长即报）。ChemDraw 的 Check Structure 变成可选补充，不是必需。
- **NMR（FR-V4）**：仍未有可信实现。ChemDraw 的 Predict 命令驱动不了，自己写经验模型又会骗人，
  所以**保持未实现**，在能力目录里写明「需本地 ChemDraw 手动预测」。这是唯一一条明确不交付的功能。
## 18. M4 落点：名称解析三层，图像识别多读者投票

- **名称/CAS（FR-I1）**：`resolve.py` 三层——本地名称表（约 40 个教学常用名，中英双语）、本地 CAS 表、
  PubChem REST。每次返回 `source` 与 `tried`，非本地命中会置 `degraded` 并说明原因。
  本机实测：阿司匹林 → 本地命中；64-17-5 → 本地 CAS 命中；未知名 + `--offline` 明确报离线。
- **图像识别（FR-I2）**：`ocr.py` 把「读者」与「裁决」分开。读者可以是 MolScribe / DECIMER / OSRA / MolVec，
  也可以是调用方（agent）自己看过图后给的 `llm_hint`。所有提议先进 RDKit，读不出来的直接淘汰；
  按 InChIKey 合并投票，≥2 个独立来源一致才算高置信，单个来源只作为候选并要求用户确认。
  **本机现状（2026-10-29）**：MolVec（Java）与 DECIMER（独立 TF venv）已装好并跑通，
  回归各 6/6 命中；MolScribe 差 `onmt` 未通，OSRA 无二进制。可用性不是布尔值：
  `chem_ocr --probe` 与 `chem_status` 会逐条给出「不可用的原因」，例如
  「molscribe: no interpreter for this engine」。
  **隔离**：每个引擎一个 venv / 一个 jar，`ocr.py` 用子进程调用；识别时主进程不加载任何深度学习框架，
  因此不会拖慢绘制路径，也不抢 ChemDraw 会话锁。
## 19. M5 落点：批改与出题（教学）

- **批改（FR-T1）**：`grade.py` 先比 InChIKey；不同则按「骨架 / 立体 / 分子式 / 官能团」解释差异。
  InChIKey 首段相同而全键不同 → 判为 `stereo`（同一骨架、立体不对）；分子式相同但连接不同 → `isomer`；
  否则 `different`。每条差异都写成老师会写在卷面上的话，而不是一个分数。
- **出题变体（FR-T2）**：`variants.py` 用 RDKit `ReplaceSubstructs` 把骨架上的 `[*]` 换成取代基，
  产物是真实分子（带 InChIKey），重复的自动合并并计数。
- 实测一条完整教学链路：苯骨架 + 4 个取代基 → 4 个变体 → 一次批量出图（联系表）→ 批改 3 份答卷
  （correct / different / isomer），全程 2 次工具调用。

## 14. 双轨架构：两条路线怎么不打架

两个软件的架构根本不同，所以不做「一个适配器兼容两者」，而是**两条独立驱动 + 一个能力表**：

- **路线 A（ChemDraw）**：64 位进程，COM 对象 + 命令面。特点：对象模型丰富、能读回、能导出。
- **路线 B（KingDraw）**：32 位，`runtime/py32` 子进程 + 本机 DLL，必要时才拉起 GUI。
  特点：不需要 license、格式转换与分子式方便、`.king` 原生。

隔离规则（硬性）：

1. 两个适配器**互不 import**，共享代码只允许 `models.py` 这类纯数据模块。
2. 各自使用独立的应用锁：`chem-draw-tool.chemdraw` 与 `chem-draw-tool.kingdraw`，**不共用一把锁**。
3. 各自独立的状态文件与能力探测；`chem_status` 分别报告，绝不合并成一个「大概可用」。
4. 跨路线只经**中性格式**（molblock / SDF / InChIKey），禁止把 `.king` 直接塞给 ChemDraw 或反向。
5. 位数隔离：64 位代码路径不加载任何 32 位组件；32 位一律走子进程，用完即收。
6. 选择由**能力表**决定（任务名 → 哪条路线能做 → 优先级），不按「谁先启动」。
7. 每条返回都带 `route` 字段，agent 永远知道这份产物是谁做的。
8. 一路异常只降级这一路：另一路不被牵连，返回里写明 `degraded.route`。

## 15. 静默运行：交付后不干扰用户

开发期可以反复开关窗口、看见 ChemDraw 蹦出来；**交付版本不允许**。硬性要求：

1. **默认不可见**：ChemDraw 以 `Visible=False` 工作；KingDraw 只在 DLL 做不到时才拉 GUI。
2. **禁抢焦点**：任何窗口用 `SW_SHOWMINNOACTIVE` 之类的非激活方式显示；禁止 `SetForegroundWindow`。
3. **禁控制台闪窗**：子进程一律 `CREATE_NO_WINDOW`；Python 侧用无窗口解释器入口。
4. **禁阻塞对话框**：错误不弹框，写日志 + 返回失败码；需要人确认时通过接口回问，不动桌面。
5. **常驻复用**：ChemDraw 启动一次后复用，任务结束**不退出**（减少反复闪窗）；KingDraw GUI 用完即关。
6. **可调试**：环境变量 `CHEM_DRAW_DEBUG_VISIBLE=1` 才显示窗口，默认关。

验收（必须实测，不是口头保证）：连续跑 10 个任务，期间统计
「前台窗口变化次数」「新增可见顶层窗口数」「用户当前窗口焦点是否被夺」——三项都必须为 0。

**实测（2026-10-27，按窗口类名统计，不按标题——标题会把本会话的 DSH 窗口算进去）**：

1. 先 `close --quit` 让应用退出，再连续交付 3 张图（乙醇、苯、苯酚，各自 1.33 / 1.35 / 1.42 s，
   合计 4.09 s，含冷启动）。
2. `windows_before = []`、`windows_after = []`、**新增可见窗口 0**、**前台窗口未变**。
3. 三项指标全部为 0；进程列表里 ChemDraw 常驻，文档在客户端断开时自动消失，不累积。

## 16. 复杂分子实测（本机，ChemDraw 25，不可见模式）

- 120 原子（PEG 链）：插入 0.10 s，文档对象 120/119，170 mm@300dpi 导出 2.30 s，24.8 KB。
- 400 原子：插入 0.27 s，文档对象 400/399，170 mm@300dpi 导出 5.29 s，**11.6 KB**。

两个结论：

1. **插入不是瓶颈**（0.27 s / 400 原子），导出是瓶颈（5.3 s），且随尺寸增长。
2. **字节数下降暴露了可读性问题**：整体缩到 170 mm 后原子被压扁，图里的信息反而更少。
   所以大分子必须「加宽画布」或「分块导出」，并给出可读性判据（FR-D12）。

- **岩沙海葵毒素（palytoxin），C129H223N3O54，186 个重原子、64 个手性中心、642 字符 SMILES**：
  一次 `draw --width-mm 170` 全流程（插入 + 导出 + 读回核对）**2.45 s**，170 mm@300 dpi，
  61.9 KB，median bond **36.5 px**，`readable: true`，`tier: medium`。这条是 C129 量级的实证。

待补实测：分块导出的拼接与编号连续性；`.king` 路线对 >300 原子结构的行为（预期会降级）。
